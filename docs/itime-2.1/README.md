# iTime 2.1 — два TFT, погода и микроконтроллер с характером

**Последняя проверенная на реальном устройстве версия: 4 ноября 2026 года.**  
**Плата:** ESP32-S3-N16R8 (16 МБ Flash, 8 МБ PSRAM).  
**Дисплеи:** два цветных SPI TFT 1,8″, 128×160, контроллер ST7735.  
**Языки:** [Русский](README.md) · [English](README.en.md).  
**Предыдущая стабильная версия:** [iTime 1.0 с LCD 1602](../../firmware/itime/). Не удаляется и не переписывается.

> План был простой: показать время. Спустя пару вечеров у нас два дисплея, отдельная задача FreeRTOS, HTTPS, JSON, мультиметр, паяльник и стойкое убеждение, что обычные часы подозрительно мало страдают при разработке.

## Что работает сейчас

| Подсистема | Результат |
|---|---|
| TFT №1 | Интернет-часы UTC+4, дата, секунды, Wi-Fi |
| TFT №2 | Погода Самары и короткая страница состояния сети |
| Расписание TFT №2 | **300 секунд погода → 5 секунд сервер → повтор** |
| OpenWeather | Сбор температуры, влажности, ветра и давления; запрос раз в 15 минут после успеха |
| Давление | **мм рт. ст.**, пересчёт из гектопаскалей |
| NTP | pool.ntp.org / time.google.com, фиксированное смещение +4 часа |
| Локальный HTTP | Панель управления состоянием и два JSON-эндпоинта |
| Два экрана | Общая SPI-шина; отдельные CS и RST |
| Без мерцания | Не очищаем весь TFT при каждом обновлении секунд |
| Новости Ubuntu | **Планируются для 2.2; ещё не реализованы** |

Это не симуляция и не красивый слайд: оба TFT, синхронизация времени и погода проверены фотографиями работающего стенда. Долговременное испытание месяцами не заявлено.

## Подключение двух TFT к ESP32-S3

**Нумерация — по надписям на модуле, контакты 1–8.** Это программный SPI: DIN, CLK и D/C общие, CS и RST раздельные.

| Пин TFT | TFT №1, часы | TFT №2, погода |
|---|---|---|
| 1 — RST | GPIO **5** | GPIO **4** |
| 2 — CS | GPIO **7** | GPIO **8** |
| 3 — D/C | GPIO **6** | GPIO **6** |
| 4 — DIN / MOSI | GPIO **17** | GPIO **17** |
| 5 — CLK / SCK | GPIO **18** | GPIO **18** |
| 6 — VCC | **3V3** | **3V3** |
| 7 — BL | **3V3** | **3V3** |
| 8 — GND | **GND** | **GND** |

**Не подавать 5 В на TFT, когда замкнута перемычка J1.** На этих платах прямо написано: J1 OPEN — питание 5 В через стабилизатор; J1 SHORT — 3,3 В в обход стабилизатора. На проверенном стенде J1 замкнута на обоих модулях, VCC подано 3,3 В.

Платы установлены на breadboard и GPIO Extension Board. Цвет пластика на шилде — не юридически обязывающая гарантия уровня напряжения. Проверяйте мультиметром, общую землю и питание BL. Не меняйте соединения под питанием.

## История ремонта — инженерный детектив с паяльником

**Акт первый: экран светит как фонарик, но ничего не показывает.** Проверили питание и сигналы: программа должна сначала инициализировать ST7735. В итоге оба экрана прошли цветовой тест и вывели надпись iTime.

**Акт второй: один экран яркий, другой выглядит так, будто подсветка ушла в неоплачиваемый отпуск.** Оказалось, у них по-разному настроена перемычка J1. Замыкание J1 на втором модуле при питании 3,3 В вернуло нормальную яркость.

**Акт третий: оставшийся тусклый дисплей отказывался впечатляться нашим программированием.** Мультиметр обнаружил плохой контакт, после исправления всё заработало. Пять минут проверки контактов сэкономили бы целый эпос гипотез, но тогда у нас не было бы этой прекрасной главы.

**Акт четвёртый: добавили HTTPS — получили http error -1.** Это транспортная ошибка HTTPClient, а не температура минус один градус. Добавили диагностику DNS/TLS, таймауты и доверенные корневые сертификаты. Проверку сертификата не отключаем: защита соединения не обязана проигрывать удобству отладки.

**Акт пятый: дисплей перерисовывался как веб-страница в 1998 году.** Перестали очищать экран каждую секунду. Теперь меняются часы, дата и статус по необходимости. Второй TFT меняет страницу раз в 5 минут и 5 секунд соответственно.

## Библиотеки и архитектура

- **Arduino core ESP32** — ESP32-S3, Wi-Fi, WebServer, FreeRTOS, NTP.
- **Adafruit GFX** — текст, фигуры, линии и оформление.
- **Adafruit ST7735/ST7789** — драйвер TFT в программном SPI.
- **Adafruit BusIO** — зависимость Adafruit.
- **ArduinoJson 7** — парсинг OpenWeather.
- **HTTPClient + WiFiClientSecure** — HTTPS, TLS с проверкой сертификатов.
- **time.h** — точное локальное время и дата.

~~~text
loop()
  ├─ Wi-Fi reconnect / NTP
  ├─ HTTP server.handleClient()
  ├─ обновление изменённых символов часов (1 сек)
  └─ TFT №2: 300 сек погода → 5 сек сервер

weatherTask (отдельная FreeRTOS-задача)
  ├─ ждать Wi-Fi и валидного времени
  ├─ DNS + HTTPS OpenWeather
  ├─ JSON → WeatherInfo под мьютексом
  └─ 15 мин после успеха / 1 мин после ошибки
~~~

Показ погоды **5 минут** и обновление погодных данных **15 минут** — разные таймеры. Смешивать их — хороший способ случайно устроить DDoS самому себе с 1,8-дюймового экрана.

## Прошивка через PowerShell

Тестовый компьютер: Windows, PowerShell, Arduino CLI, порт **COM4** (на других ПК может измениться). Папка — **C:\Users\zhoric\Downloads**.

~~~powershell
cd c:\users\zhoric\downloads
git clone https://github.com/iXimik/iTime.git
cd .\iTime\firmware\itime_2_1
copy-item .\secrets.example.h .\secrets.h
notepad .\secrets.h
~~~

В локальном secrets.h заполняются:

~~~cpp
#define WIFI_SSID "your_2_4ghz_wifi"
#define WIFI_PASSWORD "your_wifi_password"
#define OPENWEATHER_API_KEY "your_new_api_key"
~~~

Не публикуйте secrets.h в GitHub и не размещайте свой ключ OpenWeather на скриншотах. Если ключ уже показали публике, перевыпустите его. Зрители не обязаны становиться соавторами счетов за API.

~~~powershell
arduino-cli core list
arduino-cli lib list
arduino-cli compile --fqbn esp32:esp32:esp32s3 .
arduino-cli board list
arduino-cli upload -p com4 --fqbn esp32:esp32:esp32s3 .
arduino-cli monitor -p com4 --config baudrate=115200
~~~

На тестовом ПК библиотеки Adafruit GFX, ST7735 и BusIO были установлены клонированием официальных репозиториев, поскольку Arduino Library Manager выдавал 403. Проверьте, что установлен ArduinoJson 7. Старые настройки Flash 40 MHz для ESP-WROOM-32 **не переносите автоматически на ESP32-S3**.

Если исходники загружены в виде ZIP, скопируйте в папку скетча файл openweather_ca.h, а также secrets.example.h. Имя основного файла Arduino должно совпадать с именем папки скетча — либо оставьте историческую папку itime_2_0, либо переименуйте скетч для каталога itime_2_1.

## Веб-сервер

При наличии Wi-Fi браузер в локальной сети может открыть **http://IP_ESP32/**. В проверенном запуске IP был **192.168.10.45**, но DHCP может назначить другой.

| Маршрут | Назначение |
|---|---|
| **GET /** | Веб-панель состояния и погоды |
| **GET /api/status** | IP, RSSI, uptime, время |
| **GET /api/weather** | Температура, влажность, ветер, давление, время обновления и статус |

Для давления возвращаются **pressure_hpa** и **pressure_mmhg**, чтобы сохранить совместимость. Перевод: **mmHg = hPa × 0.750061683**. В TFT значение округляется, в веб-панели выводится с одним десятичным знаком.

HTTP-сервер не имеет авторизации: используйте только доверенную локальную сеть, не пробрасывайте порт 80 в Интернет. Плате ни к чему мировая известность раньше релиза 2.2.

## Диагностика

- **Wi-Fi не подключается:** сеть должна поддерживать 2,4 ГГц; проверьте SSID, пароль, RSSI и питание.
- **Темнеет экран:** проверяйте J1, VCC, BL, общий GND и разъёмы. Виноват не всегда код, даже если он написан на C++.
- **Нет погоды:** смотрите в Serial Monitor сообщения **weather dns**, **weather tls**, **weather https**, **weather error**. HTTPS-запросы зависят от интернета, времени NTP и действующего API-ключа.
- **Дисплей мигает:** не очищайте весь экран в основном цикле. Здесь обновляются отдельные поля.
- **Смена экрана кажется редкой:** всё правильно. Погода — пять минут, сервер — пять секунд. Таймер не обязан развлекать нас каждые три секунды.
